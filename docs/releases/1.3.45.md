# AllyX 1.3.45 — local pointer-lock testing build

Adds an explicit **Lock pointer** button to the overlay. While locked, mouse-wheel scrolling moves the answer and keyboard scrolling remains available. Chromium hides and locks the local system cursor; Escape releases it. Losing focus, hiding the page, or switching to click-through mode also releases the lock. A lock granted after focus was lost is immediately released.

Permission is allowed only for pointer lock from the bundled overlay web contents and its exact local URL. Other default-session permissions remain denied. Permission failures restore the button and show an actionable message.

This is a local pointer-lock reading mode, not a separately frozen remote cursor. It does not retain a fake pointer at the position before entering AllyX. Meeting software may show a stationary or hidden cursor; behavior from a second participant's view has not been verified. Normal mouse clicks resume after pressing Escape.

Validation: 195 automated tests pass; TypeScript, source lint, and diff checks pass. New tests cover wheel scrolling, Escape release, focus loss, a late permission result, and denial recovery. Native interactive pointer-lock behavior and screen-sharing behavior still require live testing.

The Apple Silicon installer is an ad-hoc-signed local test build. Public website downloads remain on 1.3.44.
